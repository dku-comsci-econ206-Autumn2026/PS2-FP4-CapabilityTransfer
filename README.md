This repository is the smallest reproducible demonstration used in the PS2 paper and the A0 poster. It compares three access regimes for a foundation model: closed API, licensed distillation, and open weights.

## Research question

How does a model provider's choice of capability-transfer openness affect downstream entry and welfare, and when can a tax, subsidy, or compute-voucher allocation improve the outcome?

## Core measure

For teacher model `T`, student baseline `S0`, budget `B`, and access regime `r`, Effective Capability-Transfer Openness is

`ECTO_T(B; r) = max[Q(S_a) - Q(S0)] / [Q(T) - Q(S0)]`

over permitted actions `a` whose resource cost is at most `B`. This baseline supplies an illustrative transfer frontier rather than estimating it from model training.

## Reproduce

Requirements: Python 3.10 or newer. **No third-party packages are needed.**

```bash
python model.py
```

The command overwrites:

- `outputs/regime_results.csv`
- `outputs/auction_results.csv`
- `outputs/fresh_run.txt`

Runnable notebook: [`PS2_demo.ipynb`](PS2_demo.ipynb) (`jupyter notebook PS2_demo.ipynb`). It imports `model.main()` and prints the two CSV files, so it produces exactly the same numbers as the command line.

### Expected output

Under `inputs/regimes.csv` and budget `0.25`:

| Regime | Entry | ECTO | Provider profit | Welfare |
|---|---|---|---|---|
| Closed API | No | 0.00 | 1.000 | 1.000 |
| Licensed distillation | Yes | 0.65 | 0.798 | 2.183 |
| Open weights | Yes | 0.80 | 0.610 | 2.520 |

The incumbent privately selects Closed API, while total modeled welfare is highest under Open weights. A tax of `0.203` on Closed API is the smallest modeled tax that makes Licensed distillation privately preferable. Once Closed API is displaced, an open-weight subsidy of `0.188` makes Open weights privately preferable to Licensed distillation.

The authors re-ran `python model.py` from an emptied `outputs/` directory on September 27, 2026 and confirmed that all three output files regenerate byte-identically.

## Auction application

One compute voucher is allocated among **five** entrants with illustrative private values `[9, 7, 6, 4, 2]`. The second-price benchmark uses truthful bids. The first-price comparison assumes 20% bid shading. Both treatments select entrant E1; payments are 7.0 and 7.2, winner utility is 2.0 and 1.8, and allocative efficiency is 1.0 in both. This single vector is a worked example, not a revenue theorem.

The analogy is partial: compute support may create common-value spillovers, applicants may face budgets, and verified social value is harder to report than private willingness to pay.

## Evidence status and limits

All parameters are transparent hypotheses chosen for a classroom demonstration. They are not estimates of an actual company or model. The result demonstrates the mechanism and identifies thresholds; it does not establish a real-world policy effect. The next study will calibrate transfer efficiency and cost ratios from documented teacher-student pairs.
